## What the algorithm does
1. Each edge has physical length and ordinary walking time.
2. GeoAI supplies predicted nearby tree cover. Traffic is measured context; temperature is a block-context Landsat surface-temperature proxy.
3. A nonnegative multiplier makes burdensome segments cost more equivalent walking time.
4. Dijkstra adds these costs along each alternative path and chooses the smallest total.
5. The same endpoints and supported graph are used for ordinary-time and friction comparisons.

**Time cost:** `length_m / 1.2` seconds.

**Transferred canopy scenario:** `time × [1 + 0.1906100893 × canopy_deficit]`.

**Assumed combined scenario:** `time × [1 + lambda × mean(canopy_deficit, traffic_burden, temperature_burden)]`, with lambda 0.5, 1 and 2.

All three factors range from 0 to 1. Equal factor weights and lambda are assumptions, not learned preferences. Temperature is joined using the existing midpoint block ID; edges crossing boundaries are not split in this first prototype. Canopy and surface temperature may double-count related conditions.

## Learning decision
- Reuse the actual pretrained tree segmentation already run on NAIP imagery.
- Retain the already-fitted Singapore distance/sun preference model only as a transferred comparison. No new training is needed.
- Do not fit XGBoost to reproduce the hand-created score and report that as behavioral accuracy.
- The existing Singapore grouped cross-validation has comparable distance-only and distance-plus-sun performance; it does not demonstrate a large improvement or validate Plano preferences.
- Traffic, heat and crossing preference weights are not supported by that dataset. Keep them as explicit scenarios unless new compatible labels are obtained.
